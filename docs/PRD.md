# 產品需求文件 (PRD) - 個人簿記系統

## 1. 專案概述
- **背景與動機**：現代人常常需要簡單有效的方法來管理個人財務。然而市面上的記帳系統往往功能過於繁雜，導致使用者難以養成持續記帳的習慣。因此，我們希望能打造一個輕量化的個人記帳系統，降低記帳門檻，幫助使用者輕鬆且迅速地掌握自身的收支明細與餘額。
- **目標用戶**：需要追蹤個人日常財務狀況的一般使用者（如學生、上班族、家庭主婦等）。
- **核心價值主張**：提供輕量、直覺、高效率的記帳體驗，將紀錄收支的步驟極簡化，同時清晰地展現當前的總量統計。

## 2. 功能需求
主要功能與對應的使用者故事（User Stories）如下：

1. **新增收入與支出紀錄**
   - 作為一般使用者，我希望能夠新增收入或支出紀錄（包含：金額、日期、分類與備註），以便精細地記錄每一筆金流的去向。
2. **編輯與刪除歷史收支紀錄**
   - 作為一般使用者，我希望能夠隨時修改或刪除先前建立的紀錄，以便修正記錯的項目或取消不成立的交易。
3. **顯示收支明細列表**
   - 作為一般使用者，我希望能夠在畫面上看到過往登錄的收支明細列表，以便快速回顧我近期的消費軌跡。
4. **自動計算並顯示目前總收入、總支出與總餘額**
   - 作為一般使用者，我希望系統能自動加總所有紀錄，並明確顯示總收入、總支出與當前餘額，以便我一句話就能評估自己的財務健康狀況。
5. **提供簡單的分類統計或圖表呈現**
   - 作為一般使用者，我希望可以瀏覽各個消費或收入分類的簡單統計（或圖表），以便清楚地看出我每月的資金都花在哪個面向，幫助將來編列預算。

## 3. 非功能需求
- **技術限制**：
  - 系統後端由 **Flask (Python)** 框架開發。
  - 前端網頁呈現使用 **Jinja2** 模板，搭配基本 HTML / CSS / JS 達成。
  - 資料庫選用 **SQLite** 來儲存所有收支相關紀錄。
- **效能考量**：操作應保持輕巧且迅速。頁面之間的切換或表單送出的載入時間需儘可能短，讓使用者體驗無縫的記帳行為。
- **安全考量**：需防範常見的 XSS / SQL Injection，並確保資料寫入庫的安全。（若為單機使用可無身份驗證，但如有上雲端需求需考量簡單的 session 防護）。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**：
  - 以 SQLite 建立紀錄表（包含日期、分類、金額、收支類型）。
  - 新增紀錄的介面和表單功能。
  - 收支明細清單總覽功能。
  - 總收入、總支出、當期結餘的加碼統計。
- **Should Have (應該有)**：
  - 能夠編輯已紀錄的項目及刪除紀錄。
  - 基本的紀錄備註欄。
  - 以日期或特定時間區段做排序或查詢。
- **Nice to Have (加分項)**：
  - 各分類的長條圖或圓餅圖（透過前端套件如 Chart.js 處理）。
  - 各分類加總的排行榜。
  - 使用者系統：如果系統被多使用者使用，則需支援註冊/登入與各別獨立的資料。
